### 2. "Checking config / status takes a long time" (deferred — needs the log)
Single-request latency, not multi-task. Suspected model + `regent`-tool round-trip
(status.get / config.show → a second model pass to phrase it aloud). **Now measurable**
via the new log:
```powershell
Get-Content "$env:USERPROFILE\.regent\logs\voice-server.log" -Tail 30 -Wait
```
Read the `[turn] asr=… brain_ttft=… first_audio=… total=…` line to localize (ASR vs brain vs tool). Then fix the dominant stage.

### 3. Butler "stuck on SPEAKING, no diagram"
Hypothesis (unconfirmed): for a visual request the model answers **without** a `present`
spec, the fallback diagram only builds at **turn end** (`finalizeVisual`), so a long spoken
answer shows only voice dots meanwhile. Confirm from the log (#2). If confirmed, the fix is
to build the reply-content fallback **progressively during `setReply`** so the diagram
appears as Regent starts speaking. Files: `features/butler/viewmodels/useButlerCall.ts`,
`features/butler/domain/visualReady.ts`.

### 4. Echo barge-in (`dfd8472`) — real-device validation
Constants (peak-hold release ~150ms, warmup 8 frames, coupling clamp, suppress 1.25×) are
theoretical. Validate on **speakers** (self-interrupt actually stops?) AND **headphones**
(a real user barge still cuts in?). Tune in `features/butler/domain/echo.ts`.
Residual flagged by the review: on a false barge the raw echo frames become the next
utterance → Regent can ASR its own voice. Mostly mitigated by preventing the false barge;
watch for it. Server-side VAD (`domain/vad.rs` hallucination filter) is a second net.

### 5. Sentence cap = 12 — tune after listening
Deliberate midpoint. If explanations feel too long/short, adjust
`MAX_SPOKEN_SENTENCES` in `regent-voice-server/src/application/turn/synth.rs`, or make it
**diagram-aware** (uncapped when a diagram carries the detail, short otherwise — needs a
`has_visual` flag plumbed from the turn loop's `FenceGate`).

### 6. Chat dictation onset — remaining lever
`50a0960` removed the `ensureVoiceServer()` latency before capture. If the first word STILL
clips, the next suspect is the WebRTC **noiseSuppression / voiceIsolation ramp-up** eating
the onset (`shared/infrastructure/mic.ts`). More invasive (relax voiceIsolation for dictation).

### 7. Prewarm on fresh installs triggers a model download
`bde85d6` prewarms at launch. On a fresh install with voice not set up, that starts a
whisper+kokoro **download at launch** (same download as first Butler open, just earlier).
If undesirable, gate `prewarmVoiceServer()` behind a "voice enabled / models present" check.
