## Coding panel — how it works

**Per-session workspace.** A session runs either in the shared artifacts
sandbox (default, unchanged) or in a real project folder opened via Open
Folder. The choice is fixed at session creation and persisted, so resuming
re-opens the same tree. `resolve_cwd` is the single place that decision is
made; every non-Desktop caller passes `None` and is byte-for-byte unchanged.

**Opening a folder JAILS the session to it.** This is the important part.
Local sessions otherwise run unsandboxed, where `ToolContext::resolve`
returns any absolute path unchecked — tolerable only while the root is a
disposable sandbox. Pointing that root at a real repo without the jail would
put the user's home dir, dotfiles, and sibling projects one bad absolute path
away. So `workspace.is_some()` is a sandbox trigger in its own right.

**Lost-update guard.** `workspace.read` returns a `rev` token (mtime+size)
that `workspace.write` must echo back. "Disable saving while busy" does NOT
cover a buffer opened *before* a code task and saved just *after* it — that
would silently clobber the agent's verified edit. A test proves the stale
save is refused and the agent's content survives.

**Binary safety.** `workspace.read` decodes strict UTF-8 (unlike
`artifacts.get`, which is lossy for read-only preview) because this path
writes back — a lossy read saved would corrupt the file. Oversized files are
refused, never truncated, for the same reason.

**Session-scoped tree.** The sandbox root is shared by every session, so the
panel used to list every artifact folder ever made. It now shows only folders
*this* conversation wrote to, derived client-side from the file paths already
on its tool rows — no store column, no migration, no new RPC. Applies to the
sandbox only (an opened folder is yours, listed in full) and only at the root
level. A session that wrote nothing lists everything: not knowing its folders
isn't the same as it having none.

**Editor is CodeMirror 6, not Monaco.** Monaco was the approved first choice
and was reversed on evidence: its editor worker can't be resolved under
Vite 8 + Rolldown by package path or alias, and `import * as monaco` drags
~9 MB of language workers in regardless of wiring (ts.worker alone is 6.9 MB).
CodeMirror needs no workers, lands at 724 kB in a lazy chunk that never
touches the chat bundle. Revisit Monaco only if VSCode-identical behavior
becomes the point.

**Editor context to the agent.** `prompt.submit` carries the open file as a
path only (the agent has file tools and the file is in its workspace, so a
path costs nothing), and a selection with its line range AND text (which a
path cannot express). Both bounded; a malformed selection degrades to the
plain file note.

## Later the same day

**Documents are now design-dynamic (the "why do all PDFs look the same"
complaint).** ADR-040 shipped theming but named the gap itself — "the quality
gap is the design layer". Colour varied; layout never did.

- PDF: a new `html` field renders model-authored markup through the existing
  Chromium sidecar instead of the fixed template. Bare fragments get a
  print-ready wrapper; a full document passes through untouched so the model's
  own `@page` rules win. Bounded at 400 kB. Preview renders the SAME markup,
  or the vision QA loop would check a document that isn't being produced.
- PPTX: slides gain `elements` — `{kind, x, y, w, h, …}` in inches, handed to
  PptxGenJS. With `layout: "blank"` the model composes the slide; on a named
  layout it decorates one. Capped at 60/slide, unknown kinds skipped.
- DOCX/XLSX deliberately unchanged: no browser path, and their output is
  content-shaped not layout-shaped. Stated rather than silently skipped.

**Playwright was never broken — just unconfigured.** Regent supports browser
control via a Playwright MCP server (`browser.rs`), but
`attach_browser_if_configured` returns SILENTLY when `REGENT_BROWSER_MCP_URL`
is unset, so the tools never enter the catalog and the model improvises with a
`playwright` CLI that isn't installed → "No playwright". `status.get` now
reports the switch and the commands to flip it.

Enabled on this machine: Playwright's Chromium was already present, the MCP
server runs at **`http://localhost:8931/sse`** (note: it binds IPv6 loopback,
so `127.0.0.1` does NOT reach it — the documented URL in `browser.rs` is
wrong for this setup), and `REGENT_BROWSER_MCP_URL` is written to
`~/.regent/.env`. The Desktop app's `merged_env` passes the whole `.env` to the
deacon it spawns, so it takes effect on the next app start. **The MCP server
itself is not a service — it must be running for browser tools to attach.**

**Memory recall write-side gap is closed.** A sweep every 2 minutes flushes the
background review for any session idle 10 minutes; `run_turn` re-stamps the
clock so an active chat is never swept mid-thought. Server-side by choice: a
client "session ended" signal would need implementing three times (CLI,
Desktop, gateway) and none of those surfaces actually knows when a
conversation is over. Idleness is the honest proxy and covers platform chats
that have no UI to hook.

## OPEN TASKS

1. **Install the rebuilt deacon.** `target/release/regent-deacon.exe` is
   fresh and contains `workspace.create` + the editor-context handling, but
   the app was running so the installed copy at
   `%LOCALAPPDATA%\Programs\Regent\bin\` was NOT replaced. Close Regent, then
   copy it over — otherwise New File/New Folder return "method not found" and
   open-file context is silently ignored. (Dev mode via `bun tauri dev` picks
   up `target/release` on its own.)

2. ~~Document generation is template-based~~ — DONE, see above.
   Original finding kept for context: Raised three times, and
   confirmed in code: `html.rs` holds ONE `REPORT_TEMPLATE` and
   `DocumentSpec` exposes no way for the model to author markup — only
   format/title/theme/content. So colors and fonts vary per document
   (`palette::generate` seeds from content) but LAYOUT never does. ADR-040
   names this exact gap: *"the quality gap is the design layer"*. The theming
   half shipped; the model-authored-design half didn't.
   **Fix:** an escape hatch letting the model pass its own HTML to the
   existing Chromium renderer, keeping the template as fallback. The sidecar,
   browser location, manifest/edit loop, and vision preview already exist —
   this is a spec field plus a render branch, not a new pipeline.

3. **Playwright / computer_use.** A screenshot showed the agent failing with
   "No playwright". Two separate things to check: (a) is Playwright actually
   installed/reachable as a tool, and (b) does screenshot/input control target
   the wrong window when Regent isn't foregrounded (the owner's own
   hypothesis, and consistent with the documented Windows active-tab quirks in
   `computer-use-windows`).

4. ~~Proactive memory recall~~ — DONE (idle sweep, see above). Original: Root-caused
   already: the review/distillation pipeline has no per-session-end trigger.
   Only a full deacon shutdown (`drain()`) flushes it, so 425/426 sessions on
   this machine have `end_reason: NULL` and 108 of 175 chats sit permanently
   under the review threshold. The gap is documented in
   `docs/others/p4-memory-retrieval-design.md` §5 but never implemented.
   **The open question:** where should "session ended" fire — new chat,
   navigate away, app background, idle timer? That's a product call, not a
   code one.

5. **CLI "chat outline isn't auto-resizing" — needs confirmation.** Likely the
   intentionally non-reflowing WelcomePanel (see `tui-resize-model-decision`),
   i.e. possibly not a bug at all. Confirm before touching.

6. **Queue polish (not requested, flagged for judgement).** Stop currently
