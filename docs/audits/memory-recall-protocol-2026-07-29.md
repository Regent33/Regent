# Frozen protocol — paired memory-recall measurement (pilot)

**Status: FROZEN.** Committed *before* the harness was written and before any
result was produced or inspected. That ordering is the §0 gate's first
requirement and is checkable in this file's git history: if a commit touching
this document is newer than the commit carrying the results, the run is void.

**Scope.** Four of the eleven memory criteria (§1 of the comparison audit):

| ID | Criterion | Why it is in the pilot |
|---|---|---|
| **b** | Recall accuracy / precision | The core claim of the whole family |
| **d** | Storage capacity | Directly measurable, and it bounds (b) |
| **e** | Relevance filtering | Same harness as (b); one extra metric |
| **c** | Recall speed | Near-free once the harness exists |

The other seven (a, f, g, h, i, j, k) stay **unscored**. They are not
measurable by this protocol and inventing a proxy for them here would fail the
validity condition.

---

## 1. Why this pilot needs no model calls

Neither system puts an LLM in its memory-retrieval path:

- **Regent** — tri-modal fusion (FTS5-BM25 + vector cosine + graph), all local.
  The embedder (`all-MiniLM-L6-v2`) runs on-device.
- **Hermes** — the built-in store injects `MEMORY.md` / `USER.md` wholesale; the
  episodic lane is BM25. No generation in either.

So **model choice is removed as a variable entirely**, which is a stronger form
of §10's "same model" than pinning one would be. Cost is therefore near zero;
the ~$5–10 ceiling is headroom, not a budget to spend.

**Consequence, declared in advance:** this measures *retrieval*, not
*end-to-end task success*. It is evidence for criteria b/c/d/e and for nothing
else. No result here may be quoted as a general "better memory" claim.

## 2. The asymmetry, named before it is measured

Hermes's built-in memory does not *rank* — below its cap it injects everything,
which is trivially 100% recall and whatever precision the corpus size implies.
Comparing "top-k" against "all of it" at a small corpus would be a category
error dressed as a measurement.

The protocol therefore measures **what reaches the model for a given query, as
the corpus grows**, and reports a curve rather than a point. The crossover — if
any — is the finding. Predictions are recorded in §7 *before* running, so
confirmation cannot be manufactured afterwards.

## 3. Corpus (identical bytes to both systems)

- Synthetic personal-assistant memory entries: preferences, facts, people,
  project details, dates. Written for this pilot, no real user data.
- Each entry ≤ 120 chars, one line, no `§` or `\n` (both stores must accept it
  verbatim; Hermes's format is `§`-delimited).
- Sizes: **N ∈ {20, 60, 200}**. 20 sits under Hermes's 2,200-char `MEMORY.md`
  cap, 60 straddles it, 200 is well past.
- Generated by a committed script from a fixed seed. The generated corpus file
  is retained as an artifact, not regenerated at score time.

## 4. Query set

- **30 queries**, frozen, committed with the corpus.
- Each has a hand-labelled **gold set** of entry ids that a correct system
  should return. Labels are written against the corpus alone, without running
  either system.
- Query mix, fixed in advance: 10 lexical (share a rare word with the gold
  entry), 10 paraphrase (no shared content word), 10 distractor-heavy (several
  near-duplicate entries differ in one detail; only one is gold).

## 5. Metrics and the failure rule

For each system, corpus size, and k ∈ {5, 10}:

- **recall@k** — fraction of gold entries returned.
- **precision@k** — fraction of returned entries that are gold. For a system
  that returns the whole corpus, this is |gold| / N by construction; that is a
  real result, not a bug, and is reported as such.
- **speed** — median and p95 wall time per query, 50 queries, warm.
- **storable** — entries the system accepted. **A refused write counts as a
  miss for every query whose gold set includes it.** Predeclared here, so it is
  a legitimate loss and not an improvised penalty.

Each system uses **its own** embedder and index. That is part of the system
under test, not a variable to control: replacing Hermes's retrieval with
Regent's would measure nothing.

## 6. Score anchors (frozen)

Applied per criterion, using the measured curve across all three N:

| Score | Anchor |
|---|---|
| 5 | Wins at every N **and** degrades gracefully past the other's cap |
| 4 | Wins at ≥ 2 of 3 N with no regression at the third |
| 3 | Mixed — wins at one N, loses at another |
| 2 | Loses at ≥ 2 of 3 N |
| 1 | Cannot perform the operation at all |

**Stability condition:** if the interval across the three N straddles an anchor
boundary, the criterion stays **unscored**. A tie is a legitimate outcome.

## 7. Predictions, recorded before running

Stated so the result can disconfirm something:

1. **b** — Regent wins at N = 200, loses or ties at N = 20 (below the cap,
   whole-corpus injection cannot miss).
2. **d** — Regent wins; Hermes refuses writes past its cap, and the audit cites
   the exact refusal site.
3. **e** — Regent wins at every N; Hermes's built-in has no filtering at all by
   its own gap G2.
4. **c** — Hermes's built-in wins on raw latency (already in the prompt, ≈ 0);
   Regent's is sub-millisecond at these N but not zero.

If (1) shows Regent winning at N = 20 as well, suspect the harness before
believing it.

## 8. Reproducibility artifacts

Retained under `docs/audits/memory-recall-2026-07-29/`: the corpus, the query
set with gold labels, both systems' raw ranked output per query, versions of
both systems, and the harness scripts. A rerun must reconstruct every number in
the result table from these alone.

## 9. What would void this run

- Editing this file after results exist (git history is the check).
- Any query, corpus entry or gold label added, removed or altered after the
  first run.
- Scoring a criterion whose interval straddles an anchor boundary.
- Quoting any number here as evidence for a criterion outside {b, c, d, e}.
